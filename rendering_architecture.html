Rendering architecture / code-derived

Mundi의 렌더링 구조

현재 작업 트리를 기준으로 추적한 결과, 이 엔진은 DirectX 11 포워드 렌더러입니다. 각 뷰포트가 임시 FSceneRenderer를 만들고, 월드에서 가시 컴포넌트를 수집한 뒤 그림자 → 불투명/데칼 → 파티클 → 후처리 → 에디터 오버레이 → 백버퍼 합성 순서로 실행합니다.

FSceneRendererone view · one execution

01 / OVERVIEW

한눈에 보면

렌더링의 소유권, 셰이딩 방식, 가시성 처리, 최종 출력 방식만 압축한 현재 구조의 핵심입니다.

01

포워드 셰이딩

UberLit 픽셀 셰이더가 재질과 모든 라이트를 즉시 계산합니다. G-Buffer나 별도 디퍼드 라이팅 패스는 없습니다.

02

뷰 단위 실행

FViewportClient::Draw마다 FSceneView와 transient FSceneRenderer를 만들고 전체 패스를 실행합니다.

03

CPU 가시성 + GPU Forward+

메시는 BVH/Frustum과 CPU HZB로 거르고, Tile ShowFlag를 켜면 카메라 Depth에서 16×16 타일별 Min/Max를 만든 뒤 GPU가 라이트 목록을 생성합니다.

04

SceneColor 핑퐁

두 장의 전체 해상도 SceneColor를 FSwapGuard로 교대하며 후처리하고 마지막에 BackBuffer로 Blit합니다.

Architecture
in one line

World Component → MeshBatch 제출 → FSceneRenderer 패스 조립 → D3D11RHI 명령 → BackBuffer 합성 구조입니다.

Lighting & Shadow inputs

Forward shader가 Base Pass에서 아래 리소스를 직접 샘플링합니다.

▦2D Shadow Atlas · 4096²

Directional / Cascades / Spot. PCF용 depth atlas.

◇Point Shadow Cube Array

1024² cube × 최대 8 slices, face별 depth render.

≈VSM 2D Atlas

Moment RTV/SRV. 설정에 따라 DepthOnly PS를 함께 사용.

ZTile Depth Range Buffer

타일별 float2(device-Z Min/Max). Compute UAV/SRV이며 디버그 패스에서는 PS t5.

#Tile Light Index Buffer

GPU가 직접 쓰는 타일당 256 uint 슬롯: count + packed(type/index). UberLit PS t2.

●Light Structured Buffers

Point t3, Spot t4 + ambient/directional CBuffer b8.

왜 디퍼드가 아닌가? Base Pass의 UberLit.hlsl이 SV_Target0 = Color, SV_Target1 = Object ID를 바로 출력하고, 그 픽셀 셰이더 안에서 라이트·그림자를 계산합니다. Normal/Albedo/Material을 여러 G-Buffer에 쌓는 단계가 없습니다.
06 / VIEW MODES

ViewMode에 따른 분기

버튼을 눌러 각 모드의 실제 경로 차이를 확인할 수 있습니다. 공통 후단은 Debug/Editor → FXAA → Composite입니다.

Prepare/Gather→Shadow→Depth Prepass→Forward+ CS→Sky + Opaque + Decal→Particle→Post FX→Common tail
  • Phong / Gouraud / Lambert는 shader macro variant로 선택
  • Tile ShowFlag는 기본 OFF이며, 꺼지거나 GPU 준비에 실패하면 PS가 전체 Point/Spot 목록을 순회
  • 빈 depth 타일은 Billboard/투명 표면 누락을 막기 위해 Near~Far 전체 범위를 보수적으로 사용
  • Viewport 메뉴에서 라이트 히트맵과 Min/Max 깊이를 각각 또는 함께 확인 가능
Prepare/Gather→Shadow→RenderLitPath→Common tail
  • 함수 이름은 LitPath지만 ViewShaderMacros에 lighting model이 없음
  • Light buffer / tile culling 단계는 실행하지 않음
  • 현재 코드상 Particle과 Modifier Post FX를 실행하지 않음
  • ShadowMaps는 모드 분기 전에 호출되어 여전히 수행됨
Prepare/Gather→Shadow→Solid → ID only→Wireframe → Color→Common tail
  • 피킹 ID를 위해 먼저 Solid/Unlit로 ID 타깃만 작성
  • Depth clear 후 Wireframe rasterizer로 SceneColor 작성
  • 끝에서 rasterizer를 Solid로 복원
  • Particle/Decal/Post Modifier 경로는 없음
Prepare/Gather→Shadow→Opaque depth build→Depth visualize→Common tail
  • Unlit Base로 SceneDepth를 먼저 채움
  • SceneDepth_PS.hlsl가 near/far와 projection을 사용해 시각화
  • 현재 구현은 중간에 BackBuffer 전체 clear를 수행
  • 멀티 뷰포트에서 앞서 합성한 영역과 간섭할 가능성이 있음

09 / OBSERVATIONS

현재 코드에서 보이는 지점

구조 설명과 별개로, 다음은 유지보수·성능 관점에서 실제 코드가 드러내는 우선 확인 후보입니다.

IMPLEMENTED · PERSISTENT GPU

Forward+ 버퍼를 Renderer가 재사용

URenderer가 Culler를 소유하고, DepthRange/LightIndex SRV·UAV는 필요한 최대 타일 수까지 grow-only로 확장한 뒤 뷰와 프레임 사이에서 재사용합니다.

HIGH · GPU STALL

Object ID 피킹이 동기 Map

1×1 staging buffer로 복사한 직후 Map(D3D11_MAP_READ)을 호출합니다. 코드 주석대로 클릭 프레임에 CPU↔GPU 동기화 stall이 생길 수 있어 비동기 readback이 적합합니다.

MEDIUM · PASS POLICY

모든 ViewMode가 먼저 Shadow를 그림

RenderShadowMaps()가 ViewMode 분기 앞에 있어 Wireframe, SceneDepth, Unlit에서도 호출됩니다. 디버그 뷰가 그림자를 소비하지 않는다면 명시적 조건으로 비용을 줄일 수 있습니다.

MEDIUM · FEATURE PARITY

Particle/Post FX가 Lit 모드에만 묶임

Unlit/WorldNormal은 이름상 같은 RenderLitPath()를 타지만 Particle과 Modifier 후처리를 건너뜁니다. 의도인지, 뷰 모드와 콘텐츠 패스가 과결합된 것인지 확인이 필요합니다.

MEDIUM · MULTI VIEW

SceneDepth가 BackBuffer 전체를 clear

일반 경로의 ViewRect 합성과 달리 SceneDepth 경로는 중간에 BackBuffer RTV 전체를 지웁니다. 4분할 중 하나만 Depth 모드일 때 이전 뷰 결과를 지울 수 있습니다.

DESIGN · OWNERSHIP

RenderManager와 SceneRenderer 역할명 불균형

실제 orchestration은 모두 FSceneRenderer에 있고 URenderManager는 얇은 accessor입니다. 향후 render scene 캐시나 persistent resource 소유권을 둘 위치를 명확히 하기 좋습니다.

DESIGN · SHADOW CULLING

Shadow caster가 카메라 Frustum 기반

현재 shadow batch는 카메라에서 보이는 컴포넌트를 중심으로 모읍니다. 화면 밖 오브젝트가 화면 안으로 그림자만 드리우는 경우 누락 여부를 테스트할 가치가 있습니다.

DESIGN · POST ORDER

Editor primitive도 FXAA는 통과함

Editor/Debug는 Modifier 후처리 뒤에 그려지지만 FXAA 앞에 있습니다. “후처리 미적용” 주석은 일반 PP에는 맞지만 최종 FXAA까지 제외한다는 뜻은 아닙니다.
